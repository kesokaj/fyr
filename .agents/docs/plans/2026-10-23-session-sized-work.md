# Plan — session-sized work   (2026-10-23)

## Why
The operator (2026-10-23, their own turn): "we always use all context … split large context into smaller tasks or phases so we get less hallucinations" and "always splitting up things the operator asks into smaller chunks … when it is time to start a new conversation give me a new prompt. Then I run /clear and run the prompt again." The same correction was logged once before (feedback.jsonl 2026-10-21T19:04:11+02:00, crew: "Start fresh sessions to keep the context small … standing approvals in the prompt, ask only outside them or for critical failures"); a repeated correction graduates into a mechanism. Evidence and alternatives: `plans/2026-10-23-research-session-sizing.md` (49 main Claude Code sessions since 2026-09-01: median peak context 573K tokens, 38 of 49 past 200K; the harness ends a task with a generic "read the handoff" line and sizes no phase to a session). The EGM deltas approved the same day (`plans/2026-10-23-research-egm.md` items 4, 5, 6) are this plan's later phases: they are the first work run under the rule, and the first measurement of it.

## Scope
In: an always-on rule that a session is one Task or one plan phase and ends at its checkpoint with a kickoff prompt; the handoff's `## Kickoff` section and its paste-ready report; phase sizing and a fourth cold-reader question in the feature skill; a peak-context metric row and per-session peaks in `sh-agent metrics`; the EGM document standards and naive-reader lens in the feature skill's cold read; a `--drift` lens on `/review`; the operator's decision on reviewer isolation (ADR-056a) and its consequence; a harness-owned auto-compact backstop on Claude Code — `sh-agent install` sets Claude Code's own `autoCompactWindow` when absent — once the operator approves the `REQUIREMENTS.md` edit it needs (D25).
Out: a token-count trigger for the model (it cannot observe its context), an automatic `/clear` (no CLI exposes one to the model; hooks are refused, R3, ADR-007), a `sh-agent next` verb (the handoff's fenced block does the job), compaction instructions in CLAUDE.md (the root holds `AGENTS.md` alone), a wholesale EGM fork or plugin install (research-egm items 1–3, 7, 8), closed plans as drift targets by default (D7).
Follow-ups noted, not built: resume cost — `bugs/INDEX.md` (50 KB) is read whole by every fresh session; a Task later makes resume read its open rows or a short `## Open` head (research-session-sizing item 6). The operator declined to run knobs by hand (2026-10-23: "I dont want to run compact myself. I want something in this harness to monitor this and trigger"), so `/autocompact` became Phase 2b; a status line with context % is display only and stays optional for them; `/clear` then `claude --resume` is the Kickoff's path.

## Interfaces

**Rule file** `rules/session-sizing.md`, frontmatter `trigger: always_on` and a one-line quoted `description:` (the shape of `rules/critical-thinking.md`), body under 1,400 bytes:
> A session is one Task or one plan phase. A plan phase ends at its Checkpoint box: tick it, write the `changes/` entry, commit, push, then write the handoff with its `## Kickoff` and END the session; the next phase begins in a fresh conversation from that kickoff. A Task ends the same way at Definition of Done step 5. A second, unrelated ask arriving in a session that has done one gets its own Kickoff in the handoff instead of being done in place. Only the operator's own words in the same turn ("continue here") keep a session past its boundary. A Trivial change needs no kickoff. Why: a long context degrades on a gradient long before it compacts, and the model cannot see its own fill; the checkpoint is the boundary it can see.

**Handoff template** gains, after `## Next Steps` (in `SKILL.md` the outer fence is four backticks so the inner ```text fence does not close it):
````markdown
## Kickoff
```text
Project: <absolute path>. Read AGENTS.md, then <handoff path>, then <plan path>; do Phase <n> — <name> only.
Standing approvals (closed set): the phase's boxes marked who: AI and the tests they name; the checkpoint's `changes/` entry, commit and push; the closing handoff. Never: a who: user box, an Open: row, a release, a deploy, a real-home install, anything outside this repository. Ask only outside the set or on a critical failure.
Done when: <the phase's Checkpoint expect, verbatim>. Then write the handoff with the next Kickoff and end the session.
```
````
The template's Standing-approvals line is fixed text with the phase name filled in; the agent never adds to the set (D17). When nothing is queued the section holds one line: `Nothing queued; start the next task in a fresh conversation.` In an unscaffolded project (no `docs/` root, so no handoff) the kickoff is printed in chat only, same text, nothing saved. Step 7 becomes three items: (1) where the handoff was saved, (2) "Run `/clear` (Claude Code) or start a new conversation (Antigravity), then paste:" followed by the Kickoff block verbatim (the nothing-queued line when that is the case), (3) the one-sentence summary; the old item 4 is folded into (2). Paths inside the Kickoff are repo-relative except `Project:` (the template's existing rule).

## Failure modes
- A CLI ignores the rule: the § 4 behavioural run shows it (n of N), the log is FAIL, the phase stays open; on Antigravity ADR-050 records that the critical-thinking rule did not hold in one run, so this rule may not either — a FAIL there is reported, not hidden.
- The rules block passes 22,000 bytes: `TestRenderedContextFitsAntigravityBlock` fails; the rule is shortened, never the pin raised.
- A Kickoff a fresh session cannot act on: `/review --resume` (the existing trail lens) names what it had to guess; fixed at the source before the checkpoint.
- A Kickoff pasted into the same session: harmless; the session re-reads the handoff.
- `metrics show` for a vendor with no session carrying a context value in the window: that vendor's over-target count is `null` and `notes` says so; never 0. Antigravity does carry context (`agy.go:228`), so with Antigravity sessions in the window it gets a number.
- `--drift` with no `<docs-root>/specs/` and no paths: "no specs to check", stop, nothing written.
- Standards unreadable by the dispatched reviewer (wrong skill directory): the brief tells it to report an incomplete read instead of a verdict (EGM's own rule); the phase's behavioural run checks the report cites a standard.

E2E criteria (yes/no, independent of how Interfaces are built):
- Golden path: a fresh conversation started with only the Kickoff from the previous phase's handoff (pasted, or `claude "$(sh-agent kickoff)"`) completes the next phase, ticks its checkpoint, and ends with a handoff whose Kickoff names the phase after it — observed for every phase after Phase 1 on Claude Code, and once on Antigravity in a sandbox for Phase 4 (skill text only, D20).
- Edge: a headless run given two unrelated tasks with the rule installed does the first, leaves the second undone and names it in its handoff's kickoff; the same run in a home without the rule does both (must-fail control, § 4).
- Metric: the per-session peaks printed by `sh-agent metrics show --json` for this plan's own sessions — identified by the `Session ID:` line of each handoff this plan writes, never by date, since `--since` takes a day and the research sessions share it — are every one under the target (300K). Baseline from the same store on the same day: 31 of 49 main Claude Code sessions since 2026-09-01 passed 300K (`.agents/scratch/egm-review/metrics/copy.db`, read-only). A session over the target is reported with its peak, not hidden.
- Drift: `/review --drift` against a fixture clone whose spec names a flag the code lacks reports `missing:` with both file:line; against the unchanged fixture it reports `no drift detected`.
