# Review — sqlite-trail plan (cold read)   (2026-10-25)

Range reviewed: `.agents/docs/plans/2026-10-25-sqlite-trail.md` (a plan, not a diff), read against `REQUIREMENTS.md`, `internal/search/{store,reconcile,parse,search}.go`, `internal/memory/memory.go`, `internal/trail/trail.go`, `internal/dream/collect.go`, `agents/*/agent.md` tools lists, and measured counts of `.agents/docs`.

## Status: COMPLETE

## Verdict: REQUEST CHANGES

The plan is not ready for implementation. The worst problems:
1. The plan's one named requirement edit (R0, R7) is not enough: R3, R4's neighbours, R8 and Known limits restate the same facts and would be left false. Requirements are immutable, so this must be in the Phase 0 text.
2. The export format as written does not round-trip: the escape rule is not injective.
3. "Live"/"closed" is undefined for 8 of the ~14 kinds, and the import, `list --open`, the prune and the Phase 2/4 expectations all depend on it.
4. The size fallback threshold (20,000 lines) is about twice the indexer's 1 MiB per-file cap, so the file would be silently un-indexed at about 9,000 lines.
5. Agents returning their artifact as text removes the cut-off resilience the harness is built around, and doubles every artifact through the main thread's output.

Design needs revision; implementation not ready (11 BLOCKING questions below).
