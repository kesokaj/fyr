## Verdict: FINDINGS

The worst problem is `memory.Root`, the function that decides which project's memory store a command uses. The change confines the main-worktree case: the toplevel must be the directory itself or one of its parents, so `core.worktree` cannot name some other place. The linked-worktree case still returns the parent of whatever directory git reports as the common dir, and nothing checks that answer. A directory whose `.git` file points at a gitdir under the attacker's control (a `commondir` file naming another repository's `.git`) therefore resolves to that other project. `fyr memory show` then reads that project's memories into a session that is working on untrusted content. `fyr memory add`, or the dreamer, writes into that project's store, which plants text that later sessions there read as trusted memory. This behaviour existed before the range. The change narrows the hole on one branch and leaves the other open, while its doc comment says the store is confined. Nothing found is high severity. No hand-rolled crypto, no secrets, no new dependency.

## Findings
- **[medium / confidence: medium]** `internal/memory/memory.go:79-81` — In the linked-worktree branch (`gitDir != common`), `filepath.Dir(common)` is returned without checking that this worktree is registered in that common dir. Git follows a `.git` file to a gitdir and then that gitdir's `commondir` file, which may hold an absolute path. Git does not check the back-pointer during normal use. A planted checkout (an extracted archive, say) can therefore name another local repository's `.git` and get that project's root. `trusted()` only checks symlinks and tracked files in that other root, and a real project passes both. Impact: cross-project memory reads (`Show`) and writes (`Add`, dream's `Store`), which is the confused-deputy case that the new main-worktree check (lines 87-90) blocks. Remediation: in the linked branch, require that `gitDir` lies under `<common>/worktrees/` and that `<gitDir>/gitdir` names `<dir's toplevel>/.git`. Alternatively, run `git worktree list --porcelain` in `filepath.Dir(common)` and require dir's toplevel to be listed. Add a test with a forged `commondir`. A smaller issue on the main branch: `core.worktree` may still name any ancestor (for example `$HOME`, `/`), which puts the store at `~/.agents/memory`, shared by every repository that does the same. The `check-ignore` gate can be satisfied from the planted repository's own `info/exclude`. Consider requiring that `top` contains the git dir, or equals dir's own first `.git`-bearing ancestor.
- **[low / confidence: high]** `internal/harness/trailer_script_test.go:33` — The probe repository's environment is `os.Environ()` plus author settings. `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_COMMON_DIR`, `GIT_OBJECT_DIRECTORY`, `GIT_CONFIG_COUNT` and `GIT_CONFIG_PARAMETERS` are not removed, and `-C dir` does not override an exported `GIT_DIR`. Run `go test` from a hook, from `git rebase --exec`, or from an agent shell with `GIT_DIR` exported, and the test's `init`/`add`/`commit` act on the real repository (the failure class recorded for probe repositories). Remediation: build the environment with those variables removed. After `init`, assert that `git -C dir rev-parse --absolute-git-dir` prints `dir/.git` and fail otherwise.
- **[low / confidence: medium]** `internal/harness/apply.go:271-280` (`readPlain`), also `Diff` at `apply.go:316` — The file is checked with `Lstat`, then read with `os.ReadFile` (and handed to `diff`) by path. A FIFO or symlink swapped in between is followed or blocks, which is the hazard IN27 set out to close. Only someone with write access to `~/.gemini/config` can win the race, so this is the same user. Remediation: open once with `O_RDONLY|O_NOFOLLOW|O_NONBLOCK` (`syscall`), `Fstat` the descriptor, require a regular file, then read from it. For `Diff`, pass the bytes already read rather than the path, for example through a second stdin-like descriptor, or compare in memory and only shell out with both buffers.
- **[low / confidence: low]** `internal/dream/collect.go:45` → `internal/dream/run.go:506,540,616` — `oneLine` folds whitespace and fence runs but keeps `/` and `..`. `c.Name` is joined into file names (`unique(dir, day+"-"+c.Name, …)`), so a project name holding `/../` would leave the proposals, drafts or dream-failed directory. Today the name comes from the global index, which fyr writes only as `filepath.Base(root)` (`internal/search/search.go:195,254`) under a 0700 directory, so reaching this takes a same-user edit of the database. Defence in depth: on read, refuse or replace path separators and a bare `.`/`..` in `Name`, or take `filepath.Base` of it, before any file-name use.
- **[low / confidence: medium]** `internal/harness/zip.go:350-364` (`zipNamesIn`, used in `VerifyZipSums` errors) — Moved code, not new. File names taken from a SHA256SUMS the operator downloaded by hand are printed to the terminal unescaped, so control and escape bytes (ESC is not whitespace to `strings.Fields`) reach the operator's terminal from an untrusted file. Remediation: print the names with `%q`, or drop non-printable runes.
