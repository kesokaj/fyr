# Security review — v2.7.0-HEAD   (2026-10-25)

Range reviewed: commits v2.7.0..HEAD (git log v2.7.0..HEAD); the diff is git diff v2.7.0...HEAD

## Status: COMPLETE

## Verdict: FINDINGS

Worst so far: the first `fyr install` on a place that ran v2.7.0 deletes every file the old manifest lists under `~/.claude` (AGENTS.md, the CLAUDE.md stub, skills, agents, rules) with no check that the file still holds what sh-agent wrote. `~/.claude/CLAUDE.md` is Claude Code's user-memory file, which Claude Code itself appends to; anything added there since the last v2.7.0 install is removed for good.

## Findings
- **[medium / confidence: medium]** `internal/harness/apply.go:126-147` (resync loop, reached by the ADR-062 shed described at `apply.go:20-24`) — stale manifest entries are removed with `os.Remove` after only an Lstat/symlink check; no content check. v2.7.0 dropped a foreign CLAUDE.md from the manifest (`KeepForeign`/`IsOurs`, removed in this range), but a stub that was ours at the last install and edited afterwards (Claude Code `#` / `/memory` writes to `~/.claude/CLAUDE.md`) is still listed and is deleted. Also covers a hand-edited `~/.claude/AGENTS.md` or skill file. `.agents/docs/deploy/remote.md:89` documents the removal but not that edits are lost. Remediation: for the files under `.claude/`, remove only when the bytes still match what a v2.7.0 install wrote (for CLAUDE.md, the exact stub; for AGENTS.md, the old generated marker on line 1), otherwise keep and name the file with a `keep` line; or move them to a dated backup directory under the state dir instead of deleting. Add a test for an edited CLAUDE.md stub.
- **[low / confidence: medium]** `internal/dream/timer.go:315-332` with `cmd/fyr/main.go:825` — `ReplaceOldTimer` decides an old timer exists by FILE presence only, then `InstallTimer` runs `systemctl --user enable --now fyr-dream.timer` (or `launchctl bootstrap`). An operator who stopped the old timer with `systemctl --user disable --now sh-agent-dream.timer` (or `launchctl bootout`) but left the unit files has it switched back on by `fyr install`, and the nightly job then sends that machine's redacted project content to the model provider again — the one off-machine flow (R3's exception) re-enabled without the operator's word. Remediation: on Linux replace only when `systemctl --user is-enabled sh-agent-dream.timer` says enabled (on macOS when `launchctl print gui/<uid>/<label>` finds it loaded); otherwise remove the old files and print that no fyr timer was installed, with the `--install-timer` command.
- **[low / confidence: medium]** `.gitignore` (lines removed in this range: `/.claude/`, `.claude/settings.local.json`) — the repo no longer ignores Claude Code's per-repo local settings, which can carry permission grants and env values. A `.claude/settings.local.json` exists in this checkout today; it is ignored only by this box's global `~/.config/git/ignore`, not on another machine. The global git rule (stage by name) makes a commit unlikely, not impossible. Remediation: keep the two ignore lines while any machine may still run Claude Code in this tree, or delete the file.

A unit reported as off only has its files removed, and no fyr unit is written or started. With no manager on PATH the probe says on, so `InstallTimer` refuses and the old unit stays, as before. Verified as follows. The one caller (`cmd/fyr/main.go:825`) handles all four (old, replaced, dry-run) combinations, and the turned-off lines come before the replaced lines in the switch. The probe runs on a dry run too; it is read-only, and the test pins that it is the only call.
- **Finding 3 (`.gitignore` dropped `/.claude/` and `.claude/settings.local.json`): open.** It is not in this round's diff (`git diff --stat -- .gitignore` is empty) and not rebutted. It needs a fix or a rebuttal in the report's Outcome.

### New findings
- **[low / confidence: medium]** `internal/dream/timer.go:296-300` (`timerUnit.on`). `exec.Command(...).Run() == nil` takes every non-zero exit as "turned off". But `systemctl --user is-enabled` also exits non-zero when it cannot reach the user manager: an SSH session with no `XDG_RUNTIME_DIR` or user bus, a container, a box without lingering. `launchctl print` likewise fails for reasons other than "not loaded". In that case an ENABLED old timer has its files removed by `remove()`, whose `disable --now` fails the same way. The `timers.target.wants/sh-agent-dream.timer` link is then left dangling, and install prints "which was turned off", which is false. This fails in the safe direction for data leaving the machine: nothing is sent, the nightly dream just stops. It is an integrity and honesty defect, not an exposure. Remediation: read the state rather than the exit code. Run `systemctl --user is-enabled` without `--quiet`; take only `disabled` (and `masked`) as off, `enabled` as on, and anything else, including an empty stdout or a bus error on stderr, as "cannot tell", which keeps the old unit and names it. For launchd, take only "Could not find service" (exit 113) as off. Add a fake manager that exits 1 with a bus error and assert the old files stay.
- Not a finding: an old unit that is enabled but stopped (`systemctl --user stop` only) counts as on and is replaced with `enable --now`. That starts it now rather than at the next login, the same consent the enabled state already records.
