# Skill matrix — one mock scenario per skill and agent, on Antigravity

The reproducible spec behind `2026-09-03-verify-sandbox-skills.md`. Scripts are not committed (ADR-010); rebuild the kit in `.agents/scratch/skilltest/` from this file. One kit IS committed, because a release runs it unchanged: `testing/agy-rel/run.sh` (the Antigravity release rows, AGENTS.md § Release; it sources `kit-preamble.sh`). Its rows are the ids below plus its own `scaffold`, `dispatch-bugs`, `dispatch-changelog`, `dispatch-documentation` and `agents-security`. Prompts for `/grill-me` and `skill-repair` were dropped with those skills; `/grilling` is covered by the `grilling` row typed as `/grilling`.

## Procedure

1. Sandbox home `<home>` logged in to Antigravity; `fyr install --home <home>`; demo service checkouts (a three-file Go HTTP service with `/healthz` and `/hello`, scaffolded by `/init-project`, plus the `/version` task). Seeds: three identical tooling corrections appended to `<home>/.config/fyr/feedback.jsonl`; for the `bug` row, commit `sed -i 's/name = strings.TrimSpace(name)/name = strings.TrimLeft(name, " ")/' internal/greet/greet.go`.
2. Per row: fresh `git clone` of the demo into `/home/<user>/sandbox/runs/agy-<id>`, base as in the table, then
   - `HOME=<home> agy -p "The project root is the current directory, <dir>; ignore any other checkout. <prompt>" --mode accept-edits --print-timeout 20m`, with `<home>/.gemini/antigravity-cli/settings.json` written for the run (`guide.md` § 4 § Behavioural runs): `"permissions": {"allow": ["command(git)", "command(go)", "command(gofmt)", "command(cat)", "command(ls)", "command(date)", "command(mkdir)", "command(pwd)", "command(grep)", "command(find)", "command(wc)", "command(head)", "command(tail)", "command(printf)", "command(echo)", "command(cp)", "command(ln)", "command(test)", "command(diff)", "command(fyr)", "command(chmod)", "command(readlink)", "command(bash)", "command(python3)", "command(sleep)", "read_file(*)", "write_file(*)"]}` — the grant store knows four actions (`command`, `read_file`, `write_file`, `mcp`; an unknown one is logged as `ignoring invalid allow entry` in `cli.log` and skipped), and `command(<name>)` matches one command name: a `for` loop, a heredoc or a command outside the list (`node`, `docker`, `gcloud`) is denied, and the headless denial names neither the tool nor the command (BUG-141). A row whose skill text itself holds a shell construct, or reaches for a tool the sandbox lacks, runs with `command(*)` in its clone and the log says so (`edit_file(*)` and `list_dir(*)` are invalid entries in agy 1.2.8; its log names them) and `"trustedWorkspaces"` naming only the run's clone; no `toolPermission` key, checked before the batch with `grep -c toolPermission <home>/.gemini/antigravity-cli/settings.json` printing `0`; the file and the copied (or, in `testing/agy-rel/run.sh`, linked) token are deleted by name after the batch (after each row in that kit). A `command(<name>)` grant allows every argument of that command. A run counts only when its stderr has no "auto-denied" line and the newest `<home>/.gemini/antigravity-cli/log/cli-*.log` has no "invalid allow entry" line; a scenario denied a command it needs gets that one command added here, by name, in the same change. No `gcloud`, `docker`, `terraform` or `npx` is granted: a cloud command is denied, which is the mock. The grants are NOT a security boundary: the sandbox home runs as the operator's own OS user, and `go`, `git`, `bash` and `python3` can each run anything and reach the real home. They are the batch's, not a row's: the fewest the batch as a whole needs. Nothing is protected during a batch; afterwards the copied Antigravity `antigravity-oauth-token` is deleted by name. A row's `--add-dir <path>` extra is passed to `agy` as written (the init rows read the skill templates through it; the headless run also needs a `read_file(<home>/.gemini/config/skills/init-project)` allow-rule).
3. Run the check in the clone with `OUT=<stdout file>` and `SB=<home>`; exit 0 is PASS. A check cell writes each `|` as `\|`, the table's escape, so a kit built from this file unescapes it before running the check. Then read the CLI's transcript (`<home>/.gemini/antigravity-cli/conversations/*.db`, `steps.step_payload`) for skills loaded and agents dispatched, and audit every executed command for `gcloud|terraform|docker (build|run|push)|kubectl|git push|npx skills add`.
4. Drive with `xargs -P 3` under a monitor that outlives a ten-minute tool timeout. Never edit the driver while runs are in flight.
