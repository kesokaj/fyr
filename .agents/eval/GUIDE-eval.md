# GUIDE-eval — the behavioural suite

The rows `fyr eval <row>...` runs against the Antigravity CLI, each in its own
sandbox (the verb: `fyr eval --help`; the trial's steps: `internal/eval`). This
file is tracked: `fyr eval` and the auto gate read it from the checkout, and
`TestSuiteHarness` pins every row by id, agent, grants, kind and version, so a
changed row changes its `want` entry in the same commit (ADR-500, amending
ADR-091). A row's version goes up when its prompt, setup or check changes after
a trial, so old trials stop counting against the new row.

## The fixture

Every row's setup is `bash .agents/eval/fixture.sh <scenario>`, run in the
trial's clone of this checkout. It replaces the clone's history with a small
demo project (a Go greeting service: `<clone>/cmd/server`,
`<clone>/internal/greet` and its table test), removes every tag and the remote
so nothing the agent runs can reach this checkout, and seeds the records a
scenario needs into the trial home's store through `$FYR`. The scenarios:

## Writing a check

A check runs in the clone after the session, with `HOME` and `SB` set to the
trial home; `"$SB/bin/fyr"` is the fyr wrapper pinned to that home, `$OUT` and
`$OUT2` are the two sessions' outputs. A check counts only what the run added:
the fixture seeds no record of the kind a check looks for. Each check is shown
to pass on a good outcome and to fail on a bad one by `TestSuiteChecks`, which
runs the row's setup, applies the outcome, and runs the check; a new row adds
its outcomes there.

## Known limits

- The `work-start`, `work-start-host`, `work-refuse` and `work-tasks` rows test
  the lead against a stand-in verb, not real workers: the real verb's run is
  item 10's real run per runner. The stand-in checks a `Model:` line's shape,
  not `agy models`' list; `work-start-host` exercises unapproved host deferral
  in turn 1 and pre-approved `--runner host` execution in turn 2 when
  `.agents/scratch/eval/work-host-reason` is set (ADR-517); `work-refuse` covers the cold-read and workers-D-row gates
  (two prompts per row), not an unstored plan or a `- [-]` cold-read box.
- A row tests one path of its skill or agent; the baselines are n of 3 at the
  agy default model.
- The `reviewer-wide` and `reviewer-wide-bug` rows find the reviewer's
  conversation in the trial home by its definition's first sentence,
  `You are a senior code reviewer` (`TestReviewerMarker` pins both), and the
  `security` row finds the security reviewer's conversation by
  `You are the security reviewer`, skipping main-agent conversations that contain
  `<subagents>` (`BUG-545`) so reading an agent definition before `invoke_subagent`
  neither triggers false positives nor lets a main session's own searches stand in
  for the subagent's. `reviewer-wide-bug` and `security` check that
  `fyr record list --kind bug` and a directory-level `--refs <dir>/` search ran
  in the subagent's conversation, with no per-file `--refs` search inside a directory.
- A trial session knows it is in print mode (`agy -p`) only from its prompt
  (`context/AGENTS.md`, `skills/fyr-handoff/SKILL.md`), which the sandbox preamble
  supplies (`internal/sandbox/session.go`); an outside `agy -p` run that omits
  that sentence does not get a second signal.
